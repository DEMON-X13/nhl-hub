# Working in this repo

X NHL Bets: one page, one job, one state file. It began as `nhl/` in `DEMON-X13/nfl-hub` and moved
here whole on 2026-10-13. Its history before the move (every commit behind the tools, the model and
the cron slots) is in that repo: `git log 3bc336d -- nhl/ .github/workflows/nhl.yml` there.

`docs/ARCHITECTURE.md` is the deeper map: every file and what is in it, how the data flows and the
job's order. Read it when you need to find something; this file is the part you need every time.

## How the owner wants this done

Do the whole job, including the git and GitHub half, without being asked and
without narrating the steps:

- Work on a branch, commit, push, open the PR, merge it. Don't ask first, don't
  explain what a PR is or where a button lives, don't leave steps for the owner
  to do by hand. Report what landed and move on.
- Say it plainly when something is wrong, blocked, or a judgement call the owner
  actually has to make. That is the bar for interrupting -- not routine mechanics.
- Reverting is easy and the owner knows it. Prefer shipping to asking permission.
- A change is not done until `node tools/simulate.js` and `node tools/smoke.js` both end
  "0 failures" and what they ran on is committed.

## The site and its parts

GitHub Pages serves the repo root, at https://demon-x13.github.io/nhl-hub/. X NHL Bets is the NBA
Hub's idea (`DEMON-X13/nba-hub`) on hockey: moneylines, puck lines and totals, and a player props
model on trial beside DraftKings' own player prices (below). `.nojekyll` makes Pages serve the files
as they are, with no Jekyll build of the data.

## Source vs generated -- never edit a generated file

These are rebuilt from source on every scheduled run, so an edit to one is lost at the next refresh:

- `state.json`, `data/teams.json`, `data/box_*.jsonl`, `data/injuries.json`, `data/starters.json`,
  `data/players.json`, and `data/season_<year>.json` (written once, by the first run of the next
  season, from the last state of the finished one)
- `data/props.json`, `data/props_ledger.json` and `data/props_<season>.jsonl` (by `tools/props.js`: the
  projections, the shadow ledger and the record of DraftKings' closing props; the ledger and the record
  are records, so a hand edit rewrites history, and `props_check.js` fails a ledger whose frozen calls
  or grades moved)
- `data/suggest_ledger.json` (by `tools/suggest.js` in `update.js`'s second pass: the record of the suggested parlays, each
  day's levels locked at its first puck drop and graded; a record, so a hand edit rewrites history, and the smoke fails a
  ledger whose locked days or settled grades moved; `--replay`, by hand, added the days before it began)
- `tools/out/` (gitignored: the scoreboard answers a run saved, which `update.js --offline` reads)

`data/history.json` (pulled once by `tools/history.js`), `data/model.json` (written by
`tools/fit.js`) and `data/props_model.json` (written by `node tools/props.js fit`, on the finished
seasons only) are source: they change only with a deliberate pull or refit, committed with it.
`data/corr.json` (the same-game table and hold, written by `node tools/corr.js` from the finished seasons' box
scores, never by hand: `node tools/corr.js --check` measures it again and fails unless the file is exactly what it
measures) is source too; a refit of `players.js` or of the props model moves the chances it stands on, so it is
measured again then and committed with the refit.
`tools/fixtures/espn_propbets.json` is source too: ESPN's DraftKings propBets for one game as recorded on
15 October 2026, trimmed to the fields the parse reads, which `test_props.js` holds the job's parse to and the
smoke test holds the page's to.
`tools/fixtures/espn_scoreboard.json` is source too: ESPN's scoreboard as recorded on 15 October 2026,
trimmed to what the parsers read, which the smoke test holds the page's Refresh odds parse to.

## The loop

```
(cd tools && npm ci)
node tools/simulate.js        # the whole job offline in a scratch folder (today's data, its first evening, a fabricated season, the playoffs, the rollover); must end "0 failures"
node tools/update.js --scores # the first pass: the season read, scores and schedule written, every call copied from the last state, none made
node tools/fetch_box.js       # ESPN box scores (one a game, five seasons back) + the injury report (the id read from the player's link)
node tools/starters.js        # the goalies DailyFaceoff announces, game by game with their dates (answers GitHub's runners only)
node tools/players.js         # the player and goalie model: replay, report, every game to come lined up -> data/players.json ("fit" to refit)
node tools/props.js           # the props model (on trial): new finals' closing props recorded, the shadow ledger graded, frozen and called, every game through tomorrow projected -> data/props.json
node tools/update.js          # ESPN -> rate, call, freeze at puck drop, grade, simulate -> state.json; exit 1, nothing written, if a day with games to finish or call does not answer
node tools/smoke.js           # the page and the state against the injury report, the box scores, DailyFaceoff, the clock and the last published state; must end "0 failures"
node tools/sources.js         # the job's last step, after the commit: exit 1 if a source the state stands on broke

node tools/test_props.js      # the props model's own test (the parse, the distributions, the ledger end to end); must end "0 failures"
node tools/test_sgp.js        # the same-game rule's own test (tools/sgp.js, and data/corr.json holding exactly the keys it reads); must end "0 failures"
node tools/test_suggest.js    # the suggested parlays' record's own test (the grading, the summary, the check on broken ledgers, the step end to end); must end "0 failures"
node tools/suggest.js --check # the record's ledger against its rules and the last commit's (the smoke holds it too); "suggest check: 0 failures"
node tools/suggest.js --replay   # once, on a full clone (git fetch --unshallow origin main): the days before the record began, from the states the site published
node tools/corr.js --check    # the same-game table measured again (about 40 seconds): exit 1 unless data/corr.json is what it measures
node tools/corr.js            # only after a refit of players.js or the props model: measure, validate, write data/corr.json (about 6 minutes)
node tools/props_check.js     # the ledger against the last commit's, the record and the box scores (the smoke runs it too); "props check: 0 failures"
node tools/props.js fit       # only for a deliberate change to the props model: constants, walk-forward and market test -> data/props_model.json (about 15 minutes)
node tools/props.js --backfill   # once: every final ESPN still serves closing props for (from 16 April 2026) into the record
node tools/fetch_box.js --refill # once after a change to the box columns: every stored line in the old shape read again (about 6 minutes)
node tools/fetch_box.js --starters # once: every stored game in which a side used two goalies read again for its plays, the starter marked (under a minute)
```

The smoke test runs from the repo root or, as `node smoke.js`, from `tools/`. DailyFaceoff answers
GitHub's runners but not every sandbox: `starters.js` failing to read it there, for that alone, is not
a fault (it says so in `data/starters.json`, and the model chooses the goalies).

The page is `index.html`, hand-written, one file, the NBA Hub's look (The look, below); it fetches `state.json` on
every load, so a page change is just an edit (bump `APP_BUILD` in it) and a data change is the
job's. The NHL has no weeks: the unit is the day (Eastern), and the page opens on a day strip.
`data/history.json` is fifteen seasons of results (2011-12 on, with the period count) pulled
once by `tools/history.js`; `tools/fit.js` chooses the model's parameters on it and writes
`data/model.json`. Refit only for a deliberate model change, and commit the new numbers with
it. The model is `tools/elo.js`: an Elo with home ice, back-to-back and rest terms, a weight for a
result past regulation and a goal-margin multiplier, plus a Poisson goals layer (each club's
scoring rates, shrunk to the league's) for the puck line and the total. A side is taken on the
moneyline, the puck line or the total only where the model's chance beats DraftKings' implied by
five points. The call (the chance, margin, total, overtime chance, the line, each side taken and whose
call it is) is made while a game is still to come and frozen at its puck drop by the clock, not only by
ESPN's state, so a game delayed past its start is not called again (nor one whose start ESPN moves
less than half a day later after the puck drop its call was made before, which the page applies too:
no bet on it, and its card says "start moved · call kept"; a game moved to another day
is a game to come again); after it, every part is copied from the last state and graded as it stands,
never recomputed. Only the job's second pass makes calls: `update.js --scores` copies every call as it
found it, so a puck drop between the two passes is graded on the call the page showed. Rows an older
job wrote after puck drop (it recomputed the puck-line side on the team Elo's margin, so 25 of the
first 57 graded games were graded on a puck-line side other than the one shown, and that record read
11-8 for picks that went 15-5) are put back once to the call shown from the inputs they kept, the team
Elo's view beside it from the replay (a final) or the ratings as they stand (a game under way): a
replay of every committed state matched the last pre-game row on every field, `elo` included, on all
61 started games, and `simulate.js` holds the rebuild to that on rows it rewrites the older job's way.
A game leaves the schedule only on the feed's word (postponed or cancelled, or moved to another day);
one a scoreboard answer merely leaves out is kept with its call, line and grade (`kept` in the state;
a score under way kept so carries the time it was read, `scoreAt`, which the card shows),
an answer with no game on a day the last state has games on is no answer, and every game taken off is
listed in `removed` with the feed's reason.

### The Parlay Builder

The second tab (`#parlays`; `#parlay`, the NFL site's name, opens it too) is nfl-hub's Parlay Builder in
hockey's terms, built in nhl v7 (13 October 2026) from a spec and its critic's changes, with the gates below.
Three bet kinds (moneyline, puck line, total) and, since nhl v11 (15 October 2026, the owner's "go for it"),
DraftKings' player lines from the props window; one Eastern day as the slate. **The suggested levels keep one leg a
game, team bets alone**, exactly as before. **The builder takes more than one leg of a game**: one side bet a game (the
moneyline or the puck line, either club), its total, and player legs, one a player a stat (two stats of one player
allowed). A second side bet on a game replaces the first, as the other side of the total does and a player's second
line in the same stat does, each said in the builder and on the slip bar (a player's in the props window too); a player's
points beside his own goals or assists are refused, said ("nearly one bet": every goal or assist is a point; DraftKings
may not take both on one ticket, and where this page is unsure what DraftKings allows it refuses); and a game takes at
most 21 legs (`GAME_LEGS_MAX`, tools/sgp.js's `MAX_GAME_LEGS`: the most its lattice prices; a 22nd is refused, said, and
a store holding more opens with the first 21). Both rules count only the legs the builder draws: a stored leg a Refresh odds
read has taken out (its line moved or pulled, stored as it was so a reload brings it back) is not in the parlay and has no row
to remove it, so it never refuses a leg, and it stays stored unless a reload would put it beside the new leg against the
published line's rule: in the new leg's slot (replaced, said), nested with it, or past 21 of the game stored, and past 21 only
as many leave as bring the store back to 21, the last stored first (taken out for good, said by name and game); the same bet
stored at a number a read has moved since is in the new leg's slot (replaced, said). A refusal or a replacement said on the
slip bar goes at the visitor's next change to the builder (a leg added or taken out anywhere, a level's Add to builder, Clear
all); what the slip bar says of legs a read or the clock took out is said once and runs its own nine seconds, a refusal or a
replacement said over it hiding it only while that stands, and a leg it says is left out of the parlay drops out of it once the
builder draws that leg. A game priced at another book, or a publish with no same-game table, takes one leg a game, as before;

  name making a save), and the mark is trusted only where every other goalie of the side made a save of his own: a starter

  registered record, still grades every goalie who played (its own rule, unchanged here). A final whose box score is not

### The player model

The player model (`tools/players.js`) is the NBA Hub's idea: every skater an offence and a defence
rating, every goalie a save rating, in goals a game for a player on the ice all game; a club is its
lineup weighted by ice time plus its goalie; after a final the surprise in regulation goals moves
who was on the ice. Fitted on 2022-23 to 2024-25 with 2025-26 held out, and scored cold season by
season (walk-forward); `report.use` in `players.json` is whether it beat the team Elo cold, and only
then does the page's call switch to it (`by: 'players'` on the game row, the Elo's view kept beside
it as `elo`). Do not tune it on the season in progress. Each game's lineup (WHO PLAYS in
`players.js`) is who dressed last, less anyone ESPN's injury report has out, on injured reserve or
suspended and anyone listed by another club or whose latest game was for one; the report is matched by
the ESPN id `fetch_box.js` reads from the player's link (the feed has no id field: before October 2026
every id was "undefined" and nobody was ever taken out), else by club and name, else by a name only one
rated player has. Day-to-day players stay in, flagged. The goalie is chosen game by game: the one
DailyFaceoff names for that game and date (Confirmed, Likely or Unconfirmed, said exactly), else the
club's goalie with the most starts in its last ten games this season (then last season's starts for the
club), never one who is out or elsewhere; on the second night of a back to back (the club's previous
game, played or not, the day before) the other goalie from the one who started that game (its box
score), or is expected to (the same choice, while it is to come, under way or not yet boxed). The team
Elo's gap it blends is its own replay of every final, this run's. The card says which, names the injury report it
was built on, and says when a club's last box score is not read yet; the page says when the injury
report or DailyFaceoff could not be read. The Players tab shows the rankings with a five-season line
each, and which report and goalies the clubs stand on.

### The props model (on trial)

The owner's go-ahead, 15 October 2026 ("yeah do props model for NHL"). `tools/props.js` projects every expected skater's
goals, assists, points, shots on goal and blocked shots and every expected goalie's saves for each game still to come
through tomorrow (Eastern), a mean and a whole distribution each, and puts itself on trial against DraftKings' own
player prices. **It suggests nothing**: no prop goes into a level, a pick, a Safe or Medium parlay or anything else
because of it, and the page never says "model says" or "edge" on a prop until the shadow ledger's bar (below) is passed,
and then only by a change of its own. Since nhl v11 a visitor can put DraftKings' own player lines in the Parlay Builder
(under The Parlay Builder, Same-game parlays and player legs), at DraftKings' price as read: the visitor's pick, never the
model's; the levels never take a prop.

- **The box files first.** `fetch_box.js` stored ESPN's "SOG" column as `sog`; in ESPN's summary that is SHOOTOUT goals
  (`shootoutGoals`), 0 in every stored game and read by nothing. Shots on goal are "S" (`shotsTotal`). Each column is
  now read by ESPN's key, else its label, and the lines keep `s` (shots), `bs` (blocked shots), `ht` (hits) and `pptoi`
  (power-play seconds) beside `toi`, `g`, `a` and `pm`; a column ESPN leaves out is left out, never written as 0, and
  shootout goals are kept under no name. `node tools/fetch_box.js --refill` read all 7,090 stored games again (none
  failed); the daily run reads up to 100 old-shape lines again should any appear. A side's skater shots equal the other
  side's goalies' shots against on 81% of the 14,184 sides, are one or two more (an empty net) on 16%, and are more
  than three off on 19 (ESPN's own slips), so the smoke holds the column, not each game.
- **The starting goalie.** ESPN's box lists a club's goalies in no set order and has no starter field, so each side's
  starter is marked `st: 1` from ESPN's plays: the first of its goalies named making a save (a "saver" on a Shot), the
  plays taken by their sequence numbers (`startersOf` in `fetch_box.js`, on every game it boxes, from the same request).
  Before 15 October 2026 the props model took the goalie who played most, which is the reliever whenever a starter is
  pulled before half the game: 425 of the 899 sides that used two goalies from 2021-22 to 15 October 2026. `node
  tools/fetch_box.js --starters` read those 871 games again once (none failed, every one marked); a single-goalie side
  needs no mark. A starter pulled with every shot he faced a goal is named by his reliever's first save (29 sides where
  the unmarked goalie made no save in less time than the marked one could be such a case, or a late reliever), and a
  side whose plays name no save is left unmarked and read as the goalie who played most. players.js still counts the
  goalie who played most as the starter (its own model, unchanged); only props.js reads the mark.
- **The model.** A skater's rate of each stat per hour on the ice is his decayed history (half-life H games, carried
  part way between seasons), shrunk toward his position's rate (forwards and defencemen apart) by M pseudo-hours; his
  mean is that rate times his expected minutes (his last eight games, as players.js projects them) times a context
  factor, (x / its average)^e, from players.js's own view of the game: his side's expected goals for goals, assists and
  points, his side's expected shots for shots, the other side's for blocks (players.js's `upcoming` now carries `sh`,
  `sa`, `lh`, `la` for this; the lineup and the goalie are players.js's WHO PLAYS). Each count is negative binomial
  (Poisson where r is null). A goalie's saves are the shots players.js expects against his side (to the power e over
  its average) times his save rate (decayed, shrunk to the league's by M shots) times a share, a normal with a fitted
  sd rounded to whole saves. The goalie it is fitted and scored on is each side's STARTER, the box files' mark, pulled or
  not (the goalie the page projects and the ledger grades), and a goalie's history is his starts; until review on 15
  October 2026 it was the goalie who played most, which left out every start a goalie was pulled from before half the
  game and fitted the share and sd on the rest (0.974 and 6.80, now 0.968 and 7.22). The constants are a grid search
  on the log-likelihood of the finished seasons only (2022-23 to 2025-26, 2021-22 warming up): `node tools/props.js
  fit` writes them with the report to `data/props_model.json` (source, sha `3830716f296a` as fitted on 15 October
  2026); the job reads it and never refits, so nothing is tuned on the season in play. Fitted: goals Poisson (H 100,
  M 10), assists r 100 (H 100, M 5), points Poisson (H 100, M 2), shots r 30 (H 50, M 2), blocks r 10 (H 50, M 2), every
  context exponent 0.5; saves H 20 (the grid's least), carry 0.5, M 32,000 shots (the grid's most: a goalie's own save
  rate barely moves his next game's saves from the league's), e 0.5, share 0.968, sd 7.22. A first search ran with a
  broken log gamma (a cache keyed by the shifted argument) and was thrown away; `test_props.js` now holds every
  log-likelihood the search uses to sum to one.
- **Walk-forward** (each season scored by constants searched only on the seasons before it, the context from
  players.js's own walk-forward parameters for that season): mean log-likelihood a player-game, higher is better,
  against a naive own-average (his own goals, shots... a game over all his earlier games, Poisson; a goalie's own
  saves a start). The model is ahead on every stat in every season:

  | Stat | 2023-24 | 2024-25 | 2025-26 |
  |---|---|---|---|
  | Goals | -0.4495 vs -0.4591 | -0.4429 vs -0.4515 | -0.4500 vs -0.4617 |
  | Assists | -0.6376 vs -0.6481 | -0.6332 vs -0.6457 | -0.6407 vs -0.6545 |
  | Points | -0.8328 vs -0.8461 | -0.8245 vs -0.8390 | -0.8341 vs -0.8513 |
  | Shots on goal | -1.5795 vs -1.6040 | -1.5452 vs -1.5755 | -1.5358 vs -1.5706 |
  | Blocked shots | -1.1650 vs -1.1830 | -1.1592 vs -1.1770 | -1.1149 vs -1.1344 |
  | Saves | -3.4185 vs -3.4559 | -3.3679 vs -3.4291 | -3.3588 vs -3.4238 |

  About 50,000 skater games and 2,800 starts a season (every start, a pulled starter's among them). The means are level
  for the skaters (goals 0.173 said, 0.171 scored in 2025-26), but saves run high, 25.0 said against 24.2 made in

## The site behaves like a website

The owner publishes a change and expects it on every device on the next load. Nothing may quietly
outrank what the job published:

- **Published data wins over anything a browser kept.** Local storage holds only what the visitor
  made: the parlay builder's legs (a player leg with DraftKings' price and the time it was read), the parlays they saved, their stake, their picks on the Parlay
  Builder and the tab they were on, under one key, `nhl_v1`. Schedule, scores, ratings, calls, lines, lineups, the standings, the playoff picture,
  the props model's projections and its ledger's numbers, and the record are read from `state.json` on every load. A leg whose game has started leaves the
  builder: its price is gone. The lines and player props Refresh odds reads from ESPN live in the page's memory alone,
  never in storage, so a reload is the published state again.
- **A routine run is silent.** The job publishes up to five times a day; the page's stamp says when,
  and that is all. Only a model change is worth a banner. What the page does say is when a source the
  calls stand on is not the latest (an injury report carried from an earlier run, no injury report,
  DailyFaceoff unread).
- **The page says which build it is.** `buildTag` in the header shows `APP_BUILD`
  (`nhl vN · YYYY-MM-DD`), so any change to the page bumps it. Without it a stale copy cannot be
  told from a current one.
- **Data fetches are `cache: 'no-store'`.** `state.json` (with a `?t=` on it too) and ESPN's
  scoreboard, which the page reads itself on opening for a game under way and, for the odds, only on a
  press of Refresh odds (with a cache-buster too), and ESPN's DraftKings propBets, only on that press
  (a cache-buster too: ESPN serves them with a fifteen-minute max-age). The HTML is served by
  GitHub Pages with its own ten-minute cache, which a reload clears; nothing else may hold data
  longer than that.

## Conventions

- **Commit messages** are prose, not bullets: what changed, why, what the simulation and the smoke
  test reported. Look at recent commits before writing one. End with the `Co-Authored-By` and
  `Claude-Session` lines the session provides.
- **Version bump.** Any page change bumps `APP_BUILD` in `index.html` (`nhl vN · YYYY-MM-DD`).
- **Visitor data is the visitor's.** A visitor's builder and saved parlays live in their browser's
  local storage only (`nhl_v1`) and are never written to the repo or anywhere else. The page's
  origin, `demon-x13.github.io`, is shared with the owner's other Pages sites, so the key's name
  stays this site's own; it is the key the page used at `nfl-hub/nhl/`, so a visitor's builder
  came with the move.
- **No secrets in the repo.** The job reads free public feeds (ESPN, DailyFaceoff) and needs no
  key. Should one ever be needed it is a repository secret, never a file.
