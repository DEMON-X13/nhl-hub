# Working in this repo

X NHL Bets: one page, one job, one state file. It began as `nhl/` in `DEMON-X13/nfl-hub` and moved
here whole on 2026-10-13. Its history before the move (every commit behind the tools, the model and
the cron slots) is in that repo: `git log 3bc336d -- nhl/ .github/workflows/nhl.yml` there.

`docs/ARCHITECTURE.md` is the deeper map: every file and what is in it, how the data flows and the
job's order. Read it when you need to find something; this file is the part you need every time.

## How the owner wants this done

Do the whole job, including the git and GitHub half, without being asked and
without narrating the steps:

- Work on a branch, commit, push, open the PR, merge it. Don't ask first, don't
  explain what a PR is or where a button lives, don't leave steps for the owner
  to do by hand. Report what landed and move on.
- Say it plainly when something is wrong, blocked, or a judgement call the owner
  actually has to make. That is the bar for interrupting -- not routine mechanics.
- Reverting is easy and the owner knows it. Prefer shipping to asking permission.
- A change is not done until `node tools/simulate.js` and `node tools/smoke.js` both end
  "0 failures" and what they ran on is committed.

## The site and its parts

GitHub Pages serves the repo root, at https://demon-x13.github.io/nhl-hub/. X NHL Bets is the NBA
Hub's idea (`DEMON-X13/nba-hub`) on hockey: moneylines, puck lines and totals. `.nojekyll` makes
Pages serve the files as they are, with no Jekyll build of the data.

| Path | What | Source of truth |
|---|---|---|
| `index.html` | The page: hand-written, one file; fetches `state.json` on every load | `index.html` |
| `state.json` | Everything the page shows: the season, rated, called and graded | generated by the job (`tools/update.js`) |
| `data/` | The history, the fitted model, the club table, box scores, the injury report, the announced goalies, the player model | `data/history.json` and `data/model.json` are source (below); the rest is the job's |
| `tools/` | The job, the models and the gates (`simulate.js`, `smoke.js`, `sources.js`) | `tools/*.js` |
| `.github/workflows/update.yml` | The job | itself |

## Source vs generated -- never edit a generated file

These are rebuilt from source on every scheduled run, so an edit to one is lost at the next refresh:

- `state.json`, `data/teams.json`, `data/box_*.jsonl`, `data/injuries.json`, `data/starters.json`,
  `data/players.json`, and `data/season_<year>.json` (written once, by the first run of the next
  season, from the last state of the finished one)
- `tools/out/` (gitignored: the scoreboard answers a run saved, which `update.js --offline` reads)

`data/history.json` (pulled once by `tools/history.js`) and `data/model.json` (written by
`tools/fit.js`) are source: they change only with a deliberate pull or refit, committed with it.
`tools/fixtures/espn_scoreboard.json` is source too: ESPN's scoreboard as recorded on 15 October 2026,
trimmed to what the parsers read, which the smoke test holds the page's Refresh odds parse to.

## The loop

```
(cd tools && npm ci)
node tools/simulate.js        # the whole job offline in a scratch folder (today's data, its first evening, a fabricated season, the playoffs, the rollover); must end "0 failures"
node tools/update.js --scores # the first pass: the season read, scores and schedule written, every call copied from the last state, none made
node tools/fetch_box.js       # ESPN box scores (one a game, five seasons back) + the injury report (the id read from the player's link)
node tools/starters.js        # the goalies DailyFaceoff announces, game by game with their dates (answers GitHub's runners only)
node tools/players.js         # the player and goalie model: replay, report, every game to come lined up -> data/players.json ("fit" to refit)
node tools/update.js          # ESPN -> rate, call, freeze at puck drop, grade, simulate -> state.json; exit 1, nothing written, if a day with games to finish or call does not answer
node tools/smoke.js           # the page and the state against the injury report, the box scores, DailyFaceoff, the clock and the last published state; must end "0 failures"
node tools/sources.js         # the job's last step, after the commit: exit 1 if a source the state stands on broke
```

The smoke test runs from the repo root or, as `node smoke.js`, from `tools/`. DailyFaceoff answers
GitHub's runners but not every sandbox: `starters.js` failing to read it there, for that alone, is not
a fault (it says so in `data/starters.json`, and the model chooses the goalies).

The page is `index.html`, hand-written, one file, the NBA Hub's look; it fetches `state.json` on
every load, so a page change is just an edit (bump `APP_BUILD` in it) and a data change is the
job's. The NHL has no weeks: the unit is the day (Eastern), and the page opens on a day strip.
`data/history.json` is fifteen seasons of results (2011-12 on, with the period count) pulled
once by `tools/history.js`; `tools/fit.js` chooses the model's parameters on it and writes
`data/model.json`. Refit only for a deliberate model change, and commit the new numbers with
it. The model is `tools/elo.js`: an Elo with home ice, back-to-back and rest terms, a weight for a
result past regulation and a goal-margin multiplier, plus a Poisson goals layer (each club's
scoring rates, shrunk to the league's) for the puck line and the total. A side is taken on the
moneyline, the puck line or the total only where the model's chance beats DraftKings' implied by
five points. The call (the chance, margin, total, overtime chance, the line, each side taken and whose
call it is) is made while a game is still to come and frozen at its puck drop by the clock, not only by
ESPN's state, so a game delayed past its start is not called again (nor one whose start ESPN moves
less than half a day later after the puck drop its call was made before, which the page applies too:
no bet on it, and its card says "start moved · call kept"; a game moved to another day
is a game to come again); after it, every part is copied from the last state and graded as it stands,
never recomputed. Only the job's second pass makes calls: `update.js --scores` copies every call as it
found it, so a puck drop between the two passes is graded on the call the page showed. Rows an older
job wrote after puck drop (it recomputed the puck-line side on the team Elo's margin, so 25 of the
first 57 graded games were graded on a puck-line side other than the one shown, and that record read
11-8 for picks that went 15-5) are put back once to the call shown from the inputs they kept, the team
Elo's view beside it from the replay (a final) or the ratings as they stand (a game under way): a
replay of every committed state matched the last pre-game row on every field, `elo` included, on all
61 started games, and `simulate.js` holds the rebuild to that on rows it rewrites the older job's way.
A game leaves the schedule only on the feed's word (postponed or cancelled, or moved to another day);
one a scoreboard answer merely leaves out is kept with its call, line and grade (`kept` in the state;
a score under way kept so carries the time it was read, `scoreAt`, which the card shows),
an answer with no game on a day the last state has games on is no answer, and every game taken off is
listed in `removed` with the feed's reason.

### The job

`.github/workflows/update.yml` runs five times a day on ESPN's free feeds, each slot queued for the
window it must land in at the 2.7 to 8.7 hours late GitHub started this job's runs in `nfl-hub` (the
night's finals and the morning lines; before 7pm Eastern; the last read before 7pm at the usual
lateness; before 10pm; the night's finals), and once on a push to `tools/` (`tools/*.js`,
`tools/package*.json`), the page or the workflow, so a change is proved on the real feeds and the state
is the new job's at once. (The lateness was measured over 15 runs in October 2026, before the move;
this repo's own is not measured yet.) The simulation first: `tools/simulate.js` plays the whole job
offline on fixtures in the feeds' own shapes. Today's real state, box scores and injury report go through the job in its order (the steps read from
`update.yml`, so a step moved there is a step moved in the simulation) with planted cases (an injured
top goalie, a skater out by name only, a goalie on another club's report, DailyFaceoff confirming a
backup with its date written as midnight GMT, naming a debut and an unconfirmed goalie dated by a GMT
stamp, a stale entry, the first night of a back to back postponed), then the refusals (a scoreboard
day unanswered, the injury report silent or empty, DailyFaceoff silent, in a new shape, or naming games
that match nothing on the schedule); the first evening after a change (games under way and not boxed,
the published calls an older job's, the night after a back to back to call) and rows an older job
rewrote after puck drop put back exactly; a fabricated season whose evening runs the two passes either
side of a puck drop and finds games under way, one still "scheduled" past its puck drop and one whose
start moved an hour, then a scoreboard answer that is blank or leaves games out (one postponed, one
moved to another day); DraftKings' ids throughout (every invented line carries ids in ESPN's real gateway
wrapping: read whole, moved with a moved line, a flipped favourite's N and P swapped, kept by the games
under way, taken afresh by a game moved to another day; answers as "Draft Kings" with no link, an over on
another number, an id in an unknown shape, links that are not URLs and links naming the event alone, then
sources.js on answers with no link, on links it cannot read, on links naming no outcome, on the totals' links alone in a shape it cannot read (broken, by market) and on run 1d's own answers (the link-less games named beside the linked ones); the same run on link-less answers changing no call field but
`line.dk`; and a started game's id changed after puck drop, which the smoke must fail); the season played out and the playoffs (a sweep, an upset, the Final); and the
rollover. On opening night, in the summer and before a schedule is out it plays what there is (last
season's starters, last season's schedule a year on) and skips what needs a game to come. `NHL_TODAY`,
`NHL_NOW`, `NHL_STATE`, `NHL_OUT`, `NHL_TEAMS`, `NHL_DATA` and `NHL_FIXTURES` are the hooks; the real
files are never touched. The job then runs `update.js --scores` (so last night's finals are boxed in
the same run, and players.js lines up on the schedule the calls are made on: both passes read every
day), `fetch_box.js`, `starters.js`, `players.js`, `update.js`, the smoke test, the commit (straight to
`main`, as "nhl-hub bot": `state.json`, `data/teams.json`, `data/box_*.jsonl`, `data/injuries.json`,
`data/starters.json`, `data/players.json` and any `data/season_*.json`), and last `sources.js`, which
fails the run after the commit when the injury report in use is over twelve hours old, has no rows or
mostly lacks ESPN ids, or DailyFaceoff answered in a shape nothing could be read from or with games
none of which matched the schedule: the page still publishes and says so on its Games tab.

### The smoke test

The smoke test holds the published state to reality, each source read on its own terms: nobody the
injury report has out, on injured reserve or suspended is in a lineup or in goal (a goalie DailyFaceoff
confirms excepted), no goalie listed on another club's report is named for his old one, a goalie named
by the rule has played for the club and, once it has three games, started one of them, a back to back
is one and its goalie is not the one who started the night before (the box score) or is named for it
(a game still to come; one under way or over and not yet boxed is not compared), DailyFaceoff's names
reach their games, no call was made after its puck drop or moved since (the last published state,
`NHL_PREV_STATE` or git's `HEAD:state.json`), no started call of that state is gone unless `removed`
gives the feed's reason, the state is the second pass's, a call that is the player model's carries its
margin, the page opened at a puck drop offers no bet on that game and calls the visitor's day Today,
and a club knocked out of the playoffs has no Cup chance. Its section THE PARLAY BUILDER holds the
builder with rules of its own, sharing nothing with the page but the state: every line's DraftKings ids in
their shape and on their number, and the ids against the run's saved answers (`NHL_OUT`, or `tools/out`
for the real state); every level worked out by brute force on the default slate and Both days (the legs
and their order, the rule line, the chance, fair chance, price and pays), the controls, the Bet amount,
Add to builder, the builder's repricing, the card (its link, note, Share text, image, Escape, Tab order),
the store an older page wrote and a junk one, a puck drop and the watch (a level finishing at once when
another game has started, the Games tab redrawn once and not again when a builder leg leaves, a leg at a
moved number never shown as in the parlay), a stale line, a whole-number total, a game priced at another
book and one with no book named, and the panel's empty states on made-up copies (no games, every game
started, no line, a two-game night, every game alike); only `state.json` and ESPN are read and only
`nhl_v1` written. Every rule is an invariant of the state it is given, so it passes on any day: the
games it plants on or clicks are taken from the day the panel shows (the Day control set where it needs a
day kept), never from the whole schedule. Its section REFRESH ODDS holds the page's own read of ESPN (below)
on a scoreboard it answers from the state, never the real feed. `NHL_HTML`
tries another page in place of `index.html`. The season is the Eastern date's
(`E.seasonOf`), nowhere else. Between seasons the first run from August closes the old one into
`data/season_<year>.json` (read beside `history.json` by `tools/hist.js`), so its results stay in
both models; a season in neither file nor the last state is refused. In the playoffs the field is the
real one, each series is played on from its real score and the bracket shows it; `phase` is preseason,
regular, postseason, over (the champion named) or offseason.

### The Parlay Builder

The second tab (`#parlays`; `#parlay`, the NFL site's name, opens it too) is nfl-hub's Parlay Builder in
hockey's terms, built in nhl v7 (13 October 2026) from a spec and its critic's changes, with the gates below.
Three bet kinds (moneyline, puck line, total), one Eastern day as the slate, **one leg a game everywhere**
(the levels, the builder, the bet buttons): two legs of one game would be a same-game parlay, which
DraftKings prices on its own terms and this page cannot (the -1.5 and the over move together in hockey), so
a parlay's chance is its legs' chances multiplied and its price DraftKings' own, their prices multiplied. A
second bet on a game replaces the first, said in the builder and on the slip bar.

- **What is offered.** A leg is offered only on a game not started by the visitor's clock (`hasStarted`)
  whose line is fresh: `line.at` is the job's last run (`S.published`, to the minute), so a number DraftKings
  has dropped is never put on a slip. Its numbers are the state's, nothing recomputed: the chance (`pHome`,
  `cover`, `ou`), the edge (`mlEdge`, `plEdge`, `ouEdge`), the price and the other side's price, whose
  margin-free share is DraftKings' **fair chance** (`legFair`; none without the other price).
- **The panel** (`#pbPanel`): Bet amount (`#pbStake`, `P.stake`, the builder's stake too, $20 to start,
  `stakeRead` as the NFL's), Build from (All, Teams only, Totals only) over three Bet types boxes, Day (today
  and tomorrow, Eastern, each offered while it has a game to come; Both days when both have a fresh line; else
  the next day with a game), and a Games fold (a game with no fresh line shown but not tickable). Notes say
  how many legs are far off the market and how many games have no line yet; a one-line notice says when the
  watch moved the slate on because every game of the day shown had started, and another when a level was
  rebuilt because one of its own games dropped the puck ("FLA @ CBJ dropped the puck: the levels were
  rebuilt without it."). Each holds while the panel is on the slate it was said on and its day is not over
  (Eastern), and goes at the visitor's next pick. A control the panel redraws (a game's box, a Day, a
  level's button) keeps the keyboard's focus, and Add to builder takes it to the builder's heading.
- **The levels** (`PB_TIERS`): Safe the likeliest pair; Medium, Aggressive and Extreme the 3-, 4- and 5-leg
  parlay with the best chance times decimal that lands 25%, 12% and 5% by the model's chance, else the
  likeliest of that size (`likeliest`). A leg qualifies with both prices, the model at 45% to 97%, its edge 0
  or more (the margin left in), no push (a whole-number line never goes in a level), and under 15 points over
  the fair chance (`FAR_OFF`; those are counted in the far-off note and flagged on the Games cards). It is
  preferred at the site's own bar (`S.edge`, so preferred is exactly the Games cards' call) and thin below it,
  used only where the calls cannot make a level, the fewest first. The search is exact (`pbSearch`/`pbBest`:
  branch and bound over every parlay of the size, pruning only what cannot reach the floor or the best found;
  the 28-game worst Both days takes under 10 ms at 4x CPU throttle), chances and prices worked in leg order
  (puck drop, the matchup, the kind), ties within 1e-12 to the lower sorted leg ids. A level's card leads
  with the fair chance, the model's beside it; Add to builder (asks before replacing other legs), Finish, a
  lock on each leg and New legs (the level's rule on the legs it has not shown, the locks kept; Reset), kept
  outside `P` (`PB_VIEW`). Empty levels say why, worked out from the picks (tick more games, more bet types,
  or Both days, only where it would help), and under two lined games the panel says so in one line.
- **The builder** (`#builder`): rows, never a table; every stored leg read again from the state on every
  draw, a game started, called off or gone, a stale line or a moved number taken out and a moved price
  updated, each said in its live line. The same pruning runs when the page loads and when the watch looks
  (every half minute, and on coming back into view) on any tab, said on the slip bar, so a Games card never
  shows a bet as in the parlay that the builder would drop, and the Games tab is redrawn once when a leg
  leaves, not at every look. A level's Add and Finish only redraw the panel when one of the level's own games
  has started (or its line gone, the job published since, the picks changed); another game's puck drop
  leaves a level as it is. The summary's figures step down to fit their tiles (two by two up to 1100px; 13px the
  least, and a figure that still will not fit takes the whole row), so none is ever cut. Four tiles: the fair chance (or the model's), DraftKings' price, what
  the stake pays, the confidence on the fair chance. Finish parlay and Save on this device (two legs or more
  each; Save keeps the builder, and reads Saved, off, whenever the builder is a parlay already in this
  device's list, so a reload never lets it be saved twice), Clear all. Pick your own legs (`#plLines`) lists the slate's
  games with a fresh line, each with the same bet block the Games cards carry. The slip bar (`#slip`) shows
  the builder on every other tab, and on this one while the builder is out of view; with no leg left it
  shows only for a few seconds after the clock took the last ones out, saying why, and that reason is kept
  in the store (`ui.bmsg`) until the builder has been drawn, so a builder emptied on another tab or before
  a reload is still explained.
- **The card** (`#pcWin`): the parlay drawn as a card, Download image (a canvas, context calls only, never a
  remote image), Share link (`{title, text}`, the DraftKings link inside the text, never a `url`), Open in
  DraftKings, and Start over from the builder. Nothing is saved by finishing. Close, Escape and a click
  outside give the focus back to the button that opened it (or Finish parlay, if the watch redrew it away).
- **Clocks.** Every time on the page is the visitor's own and names its zone ("3:30 PM PDT": the game
  tiles, the level and builder rows, Pick your own legs, the Games cards, "as read at" and the header's
  published stamp). The card, its image and its Share text go to other people, so they are in Eastern time
  and say ET.
- **DraftKings' ids** (`line.dk`): `tools/espn.js` reads them from the links ESPN carries on every price
  (`dkHref` takes the gateway's `preurl` and keeps only the event and the outcome id, never the gateway;
  it never throws), keeping an id only in its side's shape and naming the line's own number (`0ML<m>_1`,
  `0HC<m>N150_1`, `0OU<m>O650_1`...). They ride in `line`, so they are taken while a game is to come and
  frozen at its puck drop like the rest of the call. An answer with no usable link (ESPN has said "Draft
  Kings" on some runs) keeps the last state's ids for the same numbers, dated (`dk.at`, only on carried
  ids). Only the six outcome ids count as ids: an answer whose links name the event and no outcome is one
  with none, keeps its event and carries the last state's outcome ids under the same rule (never onto another
  event), and an answer with any outcome id never carries. The card opens
  `https://sportsbook.draftkings.com/?outcomes=<id>+<id>` in leg order, names every leg it cannot open and why,
  dates what it opens by the oldest read, and never promises every leg lands; with none it opens DraftKings'
  NHL page. A game ESPN prices at another book (or names no book for) is offered like any other, but its price
  is never called DraftKings', the panel and the builder name the book, and it gets no DraftKings link.
  `update.js` logs the book and how many games carry outcome ids (read, carried, an event alone) on every run,
  and how many have an id for every price they carry, so a market whose ids stop coming shows as fewer.
  `sources.js` counts each of the six outcomes on its own and fails the run (after the commit) when one
  had links on some game and not one of them gave an id in its side's shape (DraftKings or ESPN moved that
  market's shape: those legs open no slip), or when no link at all gave an outcome id; it notes, by name,
  games whose DraftKings prices carried no link or links with no outcome id even beside games that carried
  theirs, ids on another number than the line, and another book's games.
- **Saved parlays** stay the visitor's own record: graded from the scores, a leg on a game called off void,
  one off the schedule "not on the schedule" (never pending forever), a settled grade kept in the entry.
  The state lists a game called off (`removed`) for one publish only, so the first time the page sees a
  saved leg's game there it writes the void into the leg (`void: {why, at}`), which holds from then on; a
  game called off while this browser never opened the page reads "not on the schedule".

`nhl_v1` now also holds `stake`, `ui.pb` (`k` the three boxes, `off` the games unticked, `gx` the
games fold, `day`) and, until the builder is next drawn, `ui.bmsg`; a saved parlay keeps `dec` and `fair`
and, once settled, `graded`, and a saved leg on a game called off `void`.

### Refresh odds

The job reads DraftKings' game lines only when it runs, so a line on the page can be hours old by puck drop
(the owner's ask, 15 October 2026: "a refresh odds button that will pull the live lines on demand ... rather
than like a constant job"). **Refresh odds** (on the Games toolbar and under the Parlay Builder panel's
heading, 44px, with one `aria-live` status line beside each) reads ESPN's free scoreboard in the browser
(`?dates=YYYYMMDD&limit=100&_=<now>`, no-store, no custom header, so no preflight: ESPN answers with
`access-control-allow-origin: *`) for every day the Games strip shows from today on with a game still to
come, and nothing else: never on load, never on the watch or a timer. Each game's odds are taken by `ESPN`
in `index.html`, which is `tools/espn.js`'s `oddsOf` and `dkOf` word for word, and DraftKings' ids come with
the line by `carryDk`, the carry rule, which lives in `tools/espn.js` for the job's `update.js` and the page
alike (ESPN's fresh ids, or the line before's for the same numbers when the answer has none). The call's
parts that stand on the price follow by the job's `callOf`: the moneyline's edges and side; the puck line's
and the total's chances kept where the number holds and worked again where it moved by `MODEL`, which is
`tools/elo.js`'s goals layer word for word, on the row's own total, margin and gap; their edges and sides. A
market whose number and both prices hold keeps its parts exactly (the job worked its edges on unrounded
chances). A game takes the new line only while it is still to come by the visitor's clock and by ESPN's word
(one whose puck drop passes during the read, that ESPN has under way or over, or that ESPN has postponed or
cancelled keeps its line: the job takes a game called off away at its next run), only where the read is newer
than the line it replaces, and only where ESPN gave odds: a failed request, a junk answer, a game left out of
the answer or with no odds keeps its published line, and the status line counts each ("DraftKings' lines from
ESPN, read 9:12 PM EDT: 5 games, 2 moved since the last read. 1 game had no line at ESPN: its published line
stands. 1 game is postponed at ESPN: its published line stands until the job takes it off."). A line read so
is fresh (`line.refreshed`, in the page's memory alone; the job never writes it, and the smoke fails a state
that carries it), and the Games cards, the levels, the builder, the card's DraftKings link and the panel's "as
read" line all follow. The levels' cache keys on the reads that moved what they stand on (`ODDS.v`, unmoved by
a read that changed nothing), and each level keeps the visitor's place through a read (`pbCarry`): a lock
holds while its leg still qualifies at its number, New legs keeps the legs it has shown, and the level is
worked again on the new prices. The builder draws its legs on the new lines (a moved price updated, a moved
number out, said once with the read's time) but keeps them stored as they were, so nothing a read changed
reaches `nhl_v1` on a later save. A parlay card open during a read is drawn again on the new prices and ids
(said in the card), or closed when one of its legs moved or came off (said in the status line). It is all in
memory: the press writes nothing to any storage (`NO_SAVE` while it redraws), and a reload brings back the
published state, the builder's legs at their published prices with nothing said changed. A press while a read
runs does nothing; a second press reads again. The smoke's REFRESH ODDS holds it with rules of its own: the
page's parse equal to the job's on the recorded answers in `tools/fixtures`, variants of them and the answers
the run saved; the page's carry rule equal to `tools/espn.js`'s on a table of cases; the page's goals layer
equal to `tools/elo.js`'s, number for number; games ESPN has under way, postponed and cancelled kept as
published; the store after a later save and a reload on it; a lock and New legs through a read where nothing
moved and one where every price moved, by brute force; and a card open through a read.

On a phone (640px or less) the Day and Build from choices share one row equally, the Bet types and the
game tiles go two a row, and nothing on any tab is wider than the screen (the Record tables scroll inside
their card; the playoff bracket drops its points, which the odds table shows).

### The player model

The player model (`tools/players.js`) is the NBA Hub's idea: every skater an offence and a defence
rating, every goalie a save rating, in goals a game for a player on the ice all game; a club is its
lineup weighted by ice time plus its goalie; after a final the surprise in regulation goals moves
who was on the ice. Fitted on 2022-23 to 2024-25 with 2025-26 held out, and scored cold season by
season (walk-forward); `report.use` in `players.json` is whether it beat the team Elo cold, and only
then does the page's call switch to it (`by: 'players'` on the game row, the Elo's view kept beside
it as `elo`). Do not tune it on the season in progress. Each game's lineup (WHO PLAYS in
`players.js`) is who dressed last, less anyone ESPN's injury report has out, on injured reserve or
suspended and anyone listed by another club or whose latest game was for one; the report is matched by
the ESPN id `fetch_box.js` reads from the player's link (the feed has no id field: before October 2026
every id was "undefined" and nobody was ever taken out), else by club and name, else by a name only one
rated player has. Day-to-day players stay in, flagged. The goalie is chosen game by game: the one
DailyFaceoff names for that game and date (Confirmed, Likely or Unconfirmed, said exactly), else the
club's goalie with the most starts in its last ten games this season (then last season's starts for the
club), never one who is out or elsewhere; on the second night of a back to back (the club's previous
game, played or not, the day before) the other goalie from the one who started that game (its box
score), or is expected to (the same choice, while it is to come, under way or not yet boxed). The team
Elo's gap it blends is its own replay of every final, this run's. The card says which, names the injury report it
was built on, and says when a club's last box score is not read yet; the page says when the injury
report or DailyFaceoff could not be read. The Players tab shows the rankings with a five-season line
each, and which report and goalies the clubs stand on.

## The site behaves like a website

The owner publishes a change and expects it on every device on the next load. Nothing may quietly
outrank what the job published:

- **Published data wins over anything a browser kept.** Local storage holds only what the visitor
  made: the parlay builder's legs, the parlays they saved, their stake, their picks on the Parlay
  Builder and the tab they were on, under one key, `nhl_v1`. Schedule, scores, ratings, calls, lines, lineups, the standings, the playoff picture and
  the record are read from `state.json` on every load. A leg whose game has started leaves the
  builder: its price is gone. The lines Refresh odds reads from ESPN live in the page's memory alone,
  never in storage, so a reload is the published state again.
- **A routine run is silent.** The job publishes up to five times a day; the page's stamp says when,
  and that is all. Only a model change is worth a banner. What the page does say is when a source the
  calls stand on is not the latest (an injury report carried from an earlier run, no injury report,
  DailyFaceoff unread).
- **The page says which build it is.** `buildTag` in the header shows `APP_BUILD`
  (`nhl vN · YYYY-MM-DD`), so any change to the page bumps it. Without it a stale copy cannot be
  told from a current one.
- **Data fetches are `cache: 'no-store'`.** `state.json` (with a `?t=` on it too) and ESPN's
  scoreboard, which the page reads itself on opening for a game under way and, for the odds, only on a
  press of Refresh odds (with a cache-buster too). The HTML is served by
  GitHub Pages with its own ten-minute cache, which a reload clears; nothing else may hold data
  longer than that.

## Conventions

- **Commit messages** are prose, not bullets: what changed, why, what the simulation and the smoke
  test reported. Look at recent commits before writing one. End with the `Co-Authored-By` and
  `Claude-Session` lines the session provides.
- **Version bump.** Any page change bumps `APP_BUILD` in `index.html` (`nhl vN · YYYY-MM-DD`).
- **Visitor data is the visitor's.** A visitor's builder and saved parlays live in their browser's
  local storage only (`nhl_v1`) and are never written to the repo or anywhere else. The page's
  origin, `demon-x13.github.io`, is shared with the owner's other Pages sites, so the key's name
  stays this site's own; it is the key the page used at `nfl-hub/nhl/`, so a visitor's builder
  came with the move.
- **No secrets in the repo.** The job reads free public feeds (ESPN, DailyFaceoff) and needs no
  key. Should one ever be needed it is a repository secret, never a file.
